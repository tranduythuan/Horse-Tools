## Re-running it

From this directory, with PHP 8.1+ and Composer:

```bash
composer update --no-dev --optimize-autoloader
```

`composer install` reproduces the exact locked versions; `composer update` moves to the newest allowed. Commit `composer.lock` either way.

After any run, confirm the directory-access guards are still present — Composer does not delete them, but wiping the `vendor` directory by hand does:

- `index.php` in this directory, in `vendor/`, and in each package directory under `vendor/`
- `.htaccess` in this directory

## Adding another Google API

The `extra.google/apiclient-services` block in `composer.json` trims the generated service classes to the three this plugin uses, which removes 327 unused services. Add the service name to that list and re-run `composer update` if you need another.

## Verify after upgrading

The client is used in `inc/goo.php` (Google login) and `inc/gindex.php` (Indexing API). On a staging site:

1. Complete a full OAuth round trip. Confirm the `state` nonce check and the `verifiedEmail` gate still behave.
2. Submit one URL update and one status query with a real service account.

Note that the plugin now uses the namespaced `\Google\Client` and `\Google\Service\Oauth2`, not the deprecated `Google_*` aliases, and requests the `openid` / `email` / `profile` scopes.
